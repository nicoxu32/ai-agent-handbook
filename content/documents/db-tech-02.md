# 讲讲大模型的上下文窗口，以及什么是"上下文工程"？它为什么重要？

## 面试题

<!-- field:doubao/db-tech-02/title -->
讲讲大模型的上下文窗口，以及什么是"上下文工程"？它为什么重要？
<!-- /field -->

## 回答框架

<!-- field:doubao/db-tech-02/framework -->
1. 概念：上下文窗口 = 模型单次能"看见/处理"的 token 上限
2. 上下文工程的含义：围绕有限的窗口做"信息取舍与组织"——放什么、放多少、怎么排
3. 重要性：窗口有限 + 信息有优劣 → 直接决定回答质量和成本
4. 常用手段：RAG 按需捞取、摘要压缩、截断策略、提示词结构优化
<!-- /field -->

## 口述参考答案

<!-- field:doubao/db-tech-02/answer -->
"我先解释上下文窗口。它是大模型一次能同时'看见'和处理的 token 上限——你可以理解成模型的'工作记忆容量'。你给它多少输入，它处理这些输入的能力是有上限的，这个上限就是上下文窗口，比如常见的几万甚至几十万 token。超出窗口的部分，模型是看不到的。

那什么是上下文工程？既然窗口是有限的，你怎么在**有限的容量里放进对回答最有用的信息**、以及怎么把这些信息组织好，让模型发挥出最好效果——这一整套取舍和设计，就叫上下文工程。说白了就是**'在窗口内做信息管理'**：放什么、放多少、按什么顺序放。

它为什么重要？我给你讲三个原因。

**第一，窗口有限，但信息是海量的。** 企业的知识库、超长的文档，不可能全塞进去，你必须主动决定哪些信息值得占用宝贵的窗口空间。放错了、放少了，答案质量就会掉。

**第二，信息在窗口里的位置和清晰度，直接影响模型表现。** 同一段资料，怎么组织、怎么强调、放在前面还是后面，效果差别很大。比如把核心指令放前面、把用户最相关的资料放中间，通常比一股脑堆在后面更好。所以上下文工程不是玄学，是实打实影响结果的工程。

**第三，它直接和成本挂钩。** token 是计费的，塞得越多越贵、响应也越慢。好的上下文工程是用**最少的 token 拿到最好的效果**，这既是技术问题也是成本问题。

那常用手段有哪些？我重点讲两个。一个是**RAG**——通过检索把最相关的资料按需捞进窗口，而不是把整个知识库都塞进来；另一个是**摘要与压缩**——对长文档先做提炼再进窗口；再配合**提示词的结构化设计**和合理的截断策略。

所以我的理解是：上下文工程本质是**在'有限的窗口 + 有成本'这两个约束下，做信息的精确编排**。它决定了模型能不能在合适的位置看到合适的信息，从而决定回答质量，也决定了你花多少钱、多快出结果。对大模型产品来说，这是很核心的一个工程能力。"
