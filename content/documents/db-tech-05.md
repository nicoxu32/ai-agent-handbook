# 讲讲 Agent 的基本架构，它和"单次调用一次大模型"有什么本质不同？

## 面试题

<!-- field:doubao/db-tech-05/title -->
讲讲 Agent 的基本架构，它和"单次调用一次大模型"有什么本质不同？
<!-- /field -->

## 回答框架

<!-- field:doubao/db-tech-05/framework -->
1. 单次调用 vs Agent：一次问答 vs 一个"能自主规划-执行-反思-迭代"的循环
2. Agent 四要素：大模型（大脑）、工具（手脚）、记忆、规划/反思
3. 运行循环：拆解目标 → 调用工具/检索 → 观察结果 → 反思调整 → 直到完成
4. 关键工程点：多轮控制、工具调用可靠性、记忆管理、安全与失败兜底
<!-- /field -->

## 口述参考答案

<!-- field:doubao/db-tech-05/answer -->
"我先讲清一个最本质的区别：**单次调用，是模型答一次问题；Agent，是一个能自己做事的循环。** 普通调用是你问一句、它回一句就结束了；而 Agent 是你给它一个目标，它自己去**拆解 → 执行 → 看结果 → 调整 → 再做**，一直到把这个目标完成。它不再是'回答'，而是'干活'。

那它靠什么能干这种活？我讲四个核心部件，这是 Agent 的基本架构。

**第一个，大模型——它是'大脑'，负责理解和决策。** 所有思考、判断、决定下一步做什么，都靠它。

**第二个，工具（Tools）——它是'手脚'。** 这是关键。Agent 能调用外部能力：比如能去调一个 API、能去搜网页、能去操作某个系统、能去写文件。正是因为它能调用工具，它才能真的'做'事，而不是只会说。

**第三个，记忆。** 它需要记住当前任务做到哪一步了、中间得到了什么结果，甚至调用长期记忆记住过往上下文，才能不跑偏、持续往下走。

**第四个，规划和反思。** 它要把一个大目标拆成一步步的小行动，每做完一步观察结果、判断对不对，不对就调整方向。这个'规划—执行—反思'的能力，是 Agent 区别于简单调用的核心。

那它具体怎么运转？我概括成一个循环：**用户给目标 → 大模型把它拆成步骤 → 调用对应的工具去执行 → 拿到结果后判断'够了吗' → 不够就继续下一步 → 够了就把结果整理交付。** 整个过程可能要好几个来回，不是一步到位。

最后我讲几个 Agent 落地的关键工程点，这也是面试里会被追问的：

一个是**多轮和工具调用的可靠性**——工具参数传错、调用失败是常态，必须做好容错和重试，不然很容易'死循环'。另一个是**记忆管理**——上下文是有限的，怎么做摘要、怎么保留关键状态，直接决定 Agent 长任务会不会'忘了前面'。还有一个是**安全与兜底**——Agent 拥有调用外部工具的权限，意味着它有'产生真实影响'的能力，所以权限控制、高影响动作的确认、以及失败时的降级路径，是必须设计的。

所以我的理解是：Agent 的本质是**把'大模型 + 工具 + 记忆 + 规划反思'组合成一个能自主循环做事的系统**，和单次调用的差别，是它从'回答者'变成了'执行者'。这既是它的价值所在，也是它工程复杂度、安全风险都大幅上升的原因。"
