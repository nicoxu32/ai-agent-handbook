## 七、把 36 个知识点连成一张任务图

下面是一种通用组织方式，用来理解知识之间的联系，不代表任何具体平台的实际部署架构。

```mermaid
flowchart TD
    A[用户目标与业务约束] --> B[身份权限、任务状态和范围确认]
    B --> C[工作流或 Agent 选择下一步]
    C --> D[知识路径：解析、检索、重排与来源]
    C --> E[工具路径：接口或受控界面操作]
    C --> F[多模态路径：语音、图片与文档]
    D --> G[模型处理与结构化结果]
    F --> G
    G --> H[事实、业务规则与授权检查]
    H --> I[需要时由用户补充、编辑或确认]
    I --> E
    E --> J[执行回执与真实状态核验]
    J --> C
    J --> K[达成目标或明确停止，交付结果]
    C --> L[日志、评测、成本与版本记录]
    G --> L
    J --> L
```

面试时可以这样口述这张图：

“用户提出目标后，我先确认身份、范围和关键条件，再决定哪些步骤固定走工作流、哪些交给 Agent 判断。要资料就走解析检索，要实际操作就调工具。模型负责理解和生成，程序负责权限、计算和业务状态校验。关键节点请用户补充或确认，最后用真实执行结果判断任务完成。全程保留必要记录，便于评测、排错和算成本。”
