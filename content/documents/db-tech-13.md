# 讲讲"高级 RAG"（Advanced RAG）——相比基础 RAG，它通常多了哪些优化？

## 面试题

<!-- field:doubao/db-tech-13/title -->
讲讲"高级 RAG"（Advanced RAG）——相比基础 RAG，它通常多了哪些优化？
<!-- /field -->

## 回答框架

<!-- field:doubao/db-tech-13/framework -->
1. 先回顾基础 RAG 的短板：检索不够准、文档切块粗糙、query 表达不精确 → 答案质量受限
2. 优化方向一：检索前（Pre-retrieval）——query 改写/扩展、更合理的切块与索引
3. 优化方向二：检索中（Retrieval）——混合检索、重排（rerank）精挑 topK
4. 优化方向三：检索后（Post-retrieval）——上下文压缩/重排、去冗余、让答案更聚焦
5. 常见组合：混合检索 + 重排 是最典型的"高级 RAG"升级点
<!-- /field -->

## 口述参考答案

<!-- field:doubao/db-tech-13/answer -->
"先回顾一下基础 RAG 的短板，因为高级 RAG 就是冲着这些短板去的。基础 RAG 的流程是'切块 → 向量化 → 检索 → 拼进提示词生成'，但它有几个明显的弱点：**文档切得粗糙、检索结果不够准、用户的问题表达得不清楚**，导致捞回来的资料不相关，答案质量就受限。高级 RAG 就是把这几个环节分别做精，我按'检索前、检索中、检索后'三个阶段讲。

**第一阶段，检索前的优化——先把'源头'弄对。**
一个是**更精细的切块和索引**。基础 RAG 常常是一刀切成固定长度，容易把一句话、一段逻辑拦腰截断，影响检索。高级做法是**按语义、按段落结构来切**，让每一块尽量是完整有意义的单元，必要时再加一层文档结构索引。
另一个是**查询改写（Query 改写）**。用户的原始问题往往很短、很口语、甚至有歧义，直接拿去检索效果不好。高级 RAG 会让模型**先把用户问题改写成更适合检索的形式**——比如扩展关键词、把问题改得更完整，甚至拆成多个子查询。这一招对提升召回质量特别有效。

**第二阶段，检索中的优化——把'捞回来'的弄准。**
最典型的是两件事：**混合检索**和**重排（Rerank）**。
**混合检索**是指不只靠向量相似度，还结合关键词匹配（BM25 这类）一起检索，取长补短——向量擅长抓语义，关键词擅长抓精确词，混合能覆盖更多情况。
**重排**更关键。粗检索可能捞回 50 条，里面很多是凑数的。重排就是用**一个更强的模型，对这 50 条按相关性重新精排**，把最准的 top5、top10 挑出来再喂给大模型。这个'先粗召回、再精重排'的两段式，是高级 RAG 里性价比最高、最常见的升级点。

**第三阶段，检索后的优化——把'喂进去的'弄干净。**
有时候捞回来的几段内容重复、有冗余，全塞进提示词反而干扰模型。高级 RAG 会做**上下文压缩和去重**——把重复的删掉、把不相关的裁掉，甚至对长段落做摘要，只保留真正对回答有用、且不冲突的信息，让模型在干净的上下文上生成更准确的答案。

最后我总结一下：高级 RAG 的本质，是在**基础 RAG 的每个环节上做精化**——检索前把切块和查询做好，检索中用**混合检索 + 重排**把结果捞准，检索后把上下文清理干净。其中**'query 改写 + 混合检索 + 重排'**是最核心、最常用的组合。做 RAG 系统时，先跑通基础版，再按这几个环节逐个加优化，是最务实的路线。"
