# 讲讲"让大模型输出结构化数据"（比如输出 JSON）——为什么重要？一般有哪些方法？

## 面试题

<!-- field:doubao/db-tech-18/title -->
讲讲"让大模型输出结构化数据"（比如输出 JSON）——为什么重要？一般有哪些方法？
<!-- /field -->

## 回答框架

<!-- field:doubao/db-tech-18/framework -->
1. 为什么重要：AI 要接入真实系统，系统只认结构化数据，不能靠"人类读自然语言"
2. 方法一：提示词约定——明确要求"以 JSON 格式输出"+ 给格式示例
3. 方法二：JSON Mode / 结构化输出接口——模型侧保证输出合法 JSON
4. 方法三：约束解码 / Schema 约束——从生成机制上强制符合指定字段与类型
5. 关键点：仍要校验与容错，防止字段缺失、类型不对、输出被截断
<!-- /field -->

## 口述参考答案

<!-- field:doubao/db-tech-18/answer -->
"我先讲为什么结构化输出这么重要。**因为真实系统只认'结构化的数据'，不认自然语言。** 当 AI 不是'聊聊天'、而是要真正驱动业务流程时——比如把用户的意图填进一个工单、把提取的信息写进数据库、把结果传给下游系统——系统需要的是**一段格式明确、字段清晰的数据（最典型就是 JSON）**，而不是一段让程序员再去解析的散文。所以让模型稳定输出结构化数据，是 AI 从'能对话'变成'能干活'的硬要求。

那具体怎么实现？我讲几个由浅到深的方法。

**方法一，提示词约定——最基础。** 在提示词里明确告诉模型：'请以 JSON 格式输出，包含 xx、xx 这些字段，类型是什么'，再给它一个格式示例让它照着写。这个方法简单有效，很多场景够用。但它不是百分百可靠——模型有时会偷懒、字段名写错、甚至答着答着格式崩了。

**方法二，用模型的'JSON 模式'接口。** 现在主流模型基本都提供了类似 **JSON Mode / 结构化输出**的能力——你在调用时指定'我要 JSON 输出'，模型端就会**保证它输出的是一段合法、可解析的 JSON**。这一步比纯靠提示词稳很多，因为它是在模型层面做了保证。

**方法三，约束解码 / 按 Schema 强制生成——最严格。** 更进一步，可以**给模型定义一个严格的输出 Schema**（比如'必须有字段 A 是字符串、字段 B 是数组'），系统在**生成过程中就按这个 Schema 去约束**——不让它生成不符合格式的词。这样能从根本上保证输出**结构正确、字段和类型都对**，是最可靠的方案，工程实现也最复杂。

最后我讲一个很关键的提醒：**无论用哪种方法，系统侧都还是要做校验和容错。** 因为模型再稳，也还是可能出现字段缺失、类型不对、输出被截断（因为 token 长度限制）的情况。所以我会**对模型的输出做一层'解析 + 校验'**——解析失败就重试、字段不对就修正或降级，绝不能假设模型输出永远完美。加上对**输出长度和 token 的控制**，防止内容被截断成不完整的 JSON。

所以我的理解是：**让模型输出结构化数据，是它接入真实系统的前提**，实现路径是'提示词约定 → JSON 模式接口 → 按 Schema 强制生成'从易到难递进，但无论多稳都要在系统侧加一层校验和容错兜底。** 把这一层做好了，AI 才能稳定地成为系统里的'干活单元'，而不是一个仅供聊天的黑箱。"
