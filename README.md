# AI 智能体学习手册网页

将原 Markdown 学习资料整理为可离线阅读的网页，包含 36 个知识点、108 道面试问答和 6 篇补充阅读。

## 在线访问

- 网站：https://nicoxu32.github.io/ai-agent-handbook/
- 仓库：https://github.com/nicoxu32/ai-agent-handbook

电脑和手机浏览器均可直接访问，无需保持本地电脑开机。在线版包含学习指南、架构图、术语、36 个知识点、108 道核心题和原文下载。

GitHub Pages 仅托管静态页面，**在线版暂不支持 AI 实时出题**；该能力需按下方说明在本地运行 Python 服务。仓库及网站均不包含模型服务密钥。将 AI 出题上线还需要后端托管、访问控制和用量限制，当前本地服务不能直接作为公共出题接口。

进度保存在当前网站、当前浏览器中。原本地网页的进度不会自动同步到在线版，手机与电脑之间也不自动同步。

## 打开网页

双击 `index.html` 可以离线阅读、搜索和练习原有题目。AI 实时出题需要启动下面的 Python 服务并配置模型。

也可以在本目录运行：

```sh
python3 server.py
```

然后打开 <http://127.0.0.1:8767>。按 `Ctrl+C` 停止服务。

服务只依赖 Python 标准库，无需安装额外运行依赖。如果此端口已被其他服务使用，请先关闭旧服务，或者使用 `python3 server.py --port 8768` 并访问对应端口。

## 接入 AI 实时出题

1. 将本目录的 `.env.example` 复制为 `.env`。
2. 在 `.env` 填写模型服务商的配置：

   ```dotenv
   HANDBOOK_API_BASE_URL=https://your-provider.example/v1
   HANDBOOK_API_KEY=your-api-key
   HANDBOOK_MODEL=your-model-name
   HANDBOOK_JSON_MODE=false
   ```

3. 使用支持 Chat Completions 的 OpenAI 兼容接口。Base URL 不含 `/chat/completions`；上面的地址与模型都是占位内容，需替换为实际值。
4. 如果服务商与模型支持 JSON object 模式，可把 `HANDBOOK_JSON_MODE` 设为 `true`。默认关闭，以兼容更多服务。
5. 网页进入「AI 出题」，点击「重新检查连接」，然后选择知识点、题型并出题。配置会在请求时读取，修改后不必重启。

API Key 仅由 Python 服务读取，不嵌入网页、不写入浏览器存储；服务不会对外提供 `.env` 文件。环境变量优先于 `.env`，不要将真实 Key 写进模板或原始 Markdown。

每次出题会将当前知识点的讲解、产品判断、三道原题及近期题目发给所选模型服务商，可能产生 API 用量。页面上的“已配置”仅表示配置齐全；实际账号权限、额度和模型兼容性以出题结果为准。

生成结果包含一道新题、口述参考答案与 1—3 个追问。服务会拒绝与原题或近期题目在文字上高度相似的结果，并提示手动重试；这不能保证语义永远不重复。超时不会自动重试，避免不知情的重复调用。

## 手机访问

电脑与手机连接同一 Wi-Fi，在电脑上运行：

```sh
python3 server.py --bind 0.0.0.0 --port 8768
```

手机浏览器访问 `http://电脑的局域网IP:8768`。电脑需保持运行，AI 出题由电脑上的服务调用；无需在手机填写 Key。此服务用于个人本机或可信局域网，未提供公网账号登录。

## 怎么用

- **项目切换**：左侧顶部选择「AI 智能体平台」或「智能硬件设备」。硬件项目目前为待补充页面，不显示 AI 项目的知识点、题目或进度。手机点击左上角菜单展开导航。
- **学习总览**：包含「学习指南与路径」「知识点任务架构图」「常用术语说明」。指南合并阅读方法与三轮路径，并保留完整案例、口述方法和来源入口。
- **知识架构图**：15 个架构节点关联全部 36 个知识点；展示目标、编排、检索、多模态、上下文、模型处理、权限确认、执行与状态恢复，以及贯穿全程的共享能力。可切换生成报告、执行业务操作、失败恢复三条路径，点击编号回看知识点。
- **知识目录**：六个模块共 36 节，可筛选全部、未学习和收藏。每节关联三道核心题和 AI 出题入口。
- **AI 面试**：包含 108 道核心题库和 AI 实时出题。题库按模块、知识点及题目／答案关键词筛选，每题可进入口述练习或回到知识讲解。
- **面试练习**：先自己回答，再展开口述答案；可选择模块、练习本节三题或随机抽题，用左右方向键切换。
- **AI 出题**：选择场景设计、问题排查或方案取舍，生成后先答题，再展开参考答案和追问。每个知识点在当前浏览器保留最近 10 道生成题。
- **全文搜索**：在当前 AI 项目内检索讲解、问题、答案和学习资料；按 `/` 聚焦搜索框，按 `Esc` 清空搜索。
- **学习进度与收藏**：阅读时点击“标记已学”或“收藏”，在「知识目录」筛选。原有浏览器存储键和记录沿用，切换项目不会清空。
- **下载原文**：页面底部可下载完整 Markdown。
- **打印**：阅读章节时使用浏览器打印，本节答案会自动展开。

进度、收藏和出题记录保存在当前浏览器；出题时会提交近期题目用于减少重复。不同浏览器、直接打开文件和本地服务的存储彼此独立；清除浏览器数据会移除记录。浏览器禁止本地存储时，记录仅本次打开有效。

## 更新内容

正文来源为仓库内的 `content/handbook.md`，后续更新以此文件为准。

修改原文后，在本目录执行：

```sh
python3 build.py
```

构建脚本依赖 Python 的 `markdown` 与 `beautifulsoup4`；如环境尚未安装，可执行：

```sh
python3 -m pip install -r requirements.txt
```

`template.html` 管理原有章节阅读与出题交互；`workspace.js` 和 `workspace.css` 管理项目导航、总览、目录、题库及知识图；`architecture.json` 存放架构节点、输入输出、关联知识点和任务路径。`build.py` 将这些文件和 Markdown 一起嵌入 `index.html`，生成文件仍可离线阅读。直接改 `index.html` 会在下次构建时被覆盖。

构建器按当前原文的 36 节、每节 3 道题与六个模块解析；若改变章节结构，需要同步调整构建脚本。构建时检查知识图覆盖全部 36 节。扩展架构图属于网页学习资料，下载的 Markdown 仍是原始手册。

后续项目入口在 `workspace.js` 的 `projects` 中登记；待补充项目可以先添加独立入口。接入正式内容时，需要增加该项目的数据加载、页面和独立学习记录；AI 项目现有存储不迁移，避免覆盖旧进度。

旧链接保持兼容：`#guide`、`#path` 指向合并后的 `#home`（路径链接定位到三轮学习区域）；`#extra0` 指向 `#architecture`；`#extra3` 指向 `#glossary`。知识点和 AI 出题路由保留。

接口格式参考：[OpenAI 官方 Chat Completions 文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。具体模型支持的参数以所选服务商文档为准。

## 发布与更新

推送到 `main` 后，GitHub Actions 会自动构建并发布到 GitHub Pages。在仓库的 Actions 页面可查看发布结果。

```sh
python3 -m pip install -r requirements.txt
python3 build.py
git add content/handbook.md index.html
git commit -m "Update handbook content"
git push
```

静态版本使用 `python3 build.py --static --output _site/index.html` 构建；此模式会说明 AI 出题的使用范围，并停止请求不存在的后端接口。本地 `index.html` 保留完整的后端接入能力。发布工作流只上传 `_site/`，不会将 Python 源码、配置文件或原始文档目录作为网站资产公开。

仓库为公开仓库，提交的源代码和学习材料可被访问。`.env`、虚拟环境和临时构建目录已被忽略；请勿在任何受 Git 管理的文件中填写真实密钥。
