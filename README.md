# AI 智能体学习手册网页

将原 Markdown 学习资料整理为可离线阅读的网页，包含 36 个知识点、108 道核心面试问答和配套阅读。

## 在线访问

- 网站：https://nicoxu32.github.io/ai-agent-handbook/
- 仓库：https://github.com/nicoxu32/ai-agent-handbook

电脑和手机浏览器均可直接访问，无需保持本地电脑开机。在线版包含学习路径、架构图、36 个知识点、108 道核心题和原文下载。

GitHub Pages 仅托管静态页面，**在线版暂不支持 AI 实时出题**；该能力需按下方说明在本地运行 Python 服务。仓库及网站均不包含模型服务密钥。将 AI 出题上线还需要后端托管、访问控制和用量限制，当前本地服务不能直接作为公共出题接口。

最近阅读位置和 AI 出题记录保存在当前浏览器，手机与电脑之间不自动同步。页面已移除学习进度、标记已学、收藏和章节头部的练习快捷入口。

## 本地阅读与编辑（推荐）

在 macOS 双击项目中的 **打开学习手册.command**。它会启动本地网页服务并打开浏览器；保持终端窗口运行，结束时按 Ctrl+C。已有新版服务时复用；旧服务占用端口时自动选择可用端口。

首次在另一台电脑安装：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python launch.py
```

也可直接运行 `.venv/bin/python server.py` 并打开 <http://127.0.0.1:8767>。本地服务包含 Markdown 渲染和编辑，需安装 requirements.txt 中的依赖，不需要独立后台或数据库。无需联网即可阅读、搜索、编辑和保存；AI 实时出题与 GitHub 发布仍需要网络。

生成的 `index.html` 可双击离线阅读，但直接打开文件时不能编辑电脑文件。文件由本地服务自动生成，已从 Git 跟踪中移除；网站发布仍由 GitHub 构建生成。

## 接入 AI 实时出题

1. 将本目录的 `.env.example` 复制为 `.env`。
2. 在 `.env` 填写模型服务商的配置：

   ```dotenv
   HANDBOOK_API_BASE_URL=https://your-provider.example/v1
   HANDBOOK_API_KEY=your-api-key
   HANDBOOK_MODEL=your-model-name
   HANDBOOK_JSON_MODE=false
   ```

3. 使用支持 Chat Completions 的 OpenAI 兼容接口。Base URL 不含 `/chat/completions`；上面的地址与模型都是占位内容，需替换为实际值。
4. 如果服务商与模型支持 JSON object 模式，可把 `HANDBOOK_JSON_MODE` 设为 `true`。默认关闭，以兼容更多服务。
5. 网页进入「AI 出题」，点击「重新检查连接」，然后选择知识点、题型并出题。配置会在请求时读取，修改后不必重启。

API Key 仅由 Python 服务读取，不嵌入网页、不写入浏览器存储；服务不会对外提供 `.env` 文件。环境变量优先于 `.env`，不要将真实 Key 写进模板或原始 Markdown。

每次出题会将当前知识点的讲解、产品判断、应用场景、常见问题、三道原题及近期题目发给所选模型服务商，可能产生 API 用量。页面上的“已配置”仅表示配置齐全；实际账号权限、额度和模型兼容性以出题结果为准。

生成结果包含一道新题、口述参考答案与 1—3 个追问。服务会拒绝与原题或近期题目在文字上高度相似的结果，并提示手动重试；这不能保证语义永远不重复。超时不会自动重试，避免不知情的重复调用。

## 手机访问

电脑与手机连接同一 Wi-Fi，在电脑上运行：

```sh
.venv/bin/python server.py --bind 0.0.0.0 --port 8768
```

手机浏览器访问 `http://电脑的局域网IP:8768`。电脑需保持运行，AI 出题由电脑上的服务调用；无需在手机填写 Key。此服务用于个人本机或可信局域网，未提供公网账号登录。

## 怎么用

- **项目切换**：左侧顶部选择「AI 智能体平台」或「智能硬件设备」。硬件项目目前为待补充页面，不显示 AI 项目的知识点或题目。手机点击左上角菜单展开导航。
- **学习总览**：包含「学习指南与路径」「知识点任务架构图」。指南保留三轮路径、架构图和面试入口，移除「这份手册怎么学」「把理解讲成方案」；常用术语的定义和例子融入对应知识点，不再单设页面。
- **知识架构图**：15 个架构节点关联全部 36 个知识点；展示目标、编排、检索、多模态、上下文、模型处理、权限确认、执行与状态恢复，以及贯穿全程的共享能力。可切换生成报告、执行业务操作、失败恢复三条路径，点击编号回看知识点。
- **知识目录**：六个模块共 36 节，每节包含口述讲解、产品判断、项目应用场景、常见问题和三道核心题；专题练习和 AI 出题从左侧「AI 面试」进入。
- **AI 面试**：包含 108 道核心题库和 AI 实时出题。题库按模块、知识点及题目／答案关键词筛选，每题可进入口述练习或回到知识讲解。
- **豆包面试题**：在「AI 面试 → 豆包面试题」查看持续增量收录的题目，按 AI 产品经理和 AI 技术栈筛选，数量由页面自动统计；支持题目与答案搜索、展开框架和口述答案、单题链接与页面编辑。此页面的「下载 Markdown」下载完整豆包题库。
- **面试练习**：先自己回答，再展开口述答案；可选择模块、练习本节三题或随机抽题，用左右方向键切换。
- **AI 出题**：选择场景设计、问题排查或方案取舍，生成后先答题，再展开参考答案和追问。每个知识点在当前浏览器保留最近 10 道生成题。
- **全文搜索**：在当前 AI 项目内检索讲解、问题、答案和学习资料；按 `/` 聚焦搜索框，按 `Esc` 清空搜索。
- **字号调整**：顶部「小／正常／大」 调整正文字号，每次 10%，范围 90%～150%；正常恢复 100%。选择保存在当前浏览器，刷新和切换页面后仍生效。
- **划词荧光笔**：选中知识点正文、面试题或答案的文字后，点击「划重点」标黄；手机长按选词后，按钮出现在屏幕下方。点击标记可取消，也可用 Tab 聚焦标记后按 Enter 或空格取消。同一道核心题在章节、题库和练习页共享标记，豆包题在列表与单题页共享标记。标记仅保存在当前浏览器，刷新后保留，不随内容发布，也不跨设备同步；清除浏览器数据会删除标记。原文更新后会尝试按文字和上下文恢复，无法准确定位的标记暂不显示。浏览器拒绝保存时会提示。
- **选词追加**：在本地网页的知识点讲解、产品判断、应用场景、常见问题或核心答案中选中文字，点击「追加内容」，填写补充并预览，再「确认追加并保存」。补充作为普通文字新段落插在所在段落之后，列表、表格、代码块在整个结构后插入。保存写入当前 Markdown 文件并自动更新阅读；失败保留补充草稿，支持下载。题目标题和豆包题只提供划重点，豆包答案可以通过顶部编辑窗口修改。
- **英文中文叫法**：英文术语旁显示中文注释，已有中文释义不重复添加；纯英文装饰文案改为中文。中文译名可搜索。编辑输入框保留原文，框下列出术语中文释义；网址、代码和模型标识保留原值。旁注不写入基础原文或豆包答案，因此不会改变既有荧光笔的位置，复制和原文下载仍使用原文。术语表集中维护于 `content/terms.json`，新增术语需补充对应条目。
- **路径导航**：顶部合并为项目／栏目／模块／当前页面一条路径，正文不重复展示面包屑。
- **编辑内容**：本地网页顶部点击「编辑内容」，保存到电脑后阅读页面自动更新，稍后可单独发布已保存内容。
- **下载原文**：页面底部可下载完整 Markdown。
- **打印**：阅读章节时使用浏览器打印，本节答案会自动展开。

最近阅读位置和出题记录保存在当前浏览器；出题时会提交近期题目用于减少重复。不同浏览器、直接打开文件和本地服务的存储彼此独立；清除浏览器数据会移除记录。浏览器禁止本地存储时，记录仅本次打开有效。

## 在页面里修改内容

1. 从本地启动入口打开网页，点击顶部 **编辑内容**，直接读取这台电脑上的 Markdown 文件。
2. 修改后点击 **保存到本地**。文件验证通过后写入磁盘，页面自动重新载入并恢复阅读位置，通常一两秒，无需手动构建或等待 GitHub。
3. 未点保存的输入会暂存在当前浏览器；关闭弹窗或刷新后重新编辑同一篇可恢复。此时尚未写入磁盘。清除浏览器数据会清除未保存草稿，可下载 Markdown 草稿备份。
4. 已保存的内容存在 `content/documents/`；关闭浏览器、停止服务或重启电脑都保留。每次替换前的旧文件保存在 `.local/backups/`，不会提交到 GitHub。
5. 积累修改后，点击页顶 **发布到 GitHub**（悬停可查看最近读取的待发布篇数）；发布只处理已经写入磁盘的文档，不包含未保存草稿。成功同步后会触发 GitHub Pages，线上网站需等待部署完成并刷新。本地阅读不受影响。

编辑弹窗底部的 **打开 Markdown 文件** 会用电脑的文本编辑器打开当前篇目的原文件；未保存草稿需先保存，避免两处编辑冲突。外部保存后点击「载入最新文件」继续在弹窗编辑，或关闭弹窗并刷新查看。弹窗内的保存只写本地，发布入口统一放在页顶。

编辑支持 Markdown：回车换行，空行分段，列表、表格和代码块保留格式。搜索、练习和下载使用同一份保存后的内容。直接用外部文本编辑器修改 Markdown 后刷新本地网页也会生效，保留文件中的 `<!-- field:... -->` 和结束标记。

发布复用本机 Git 认证，无需在网页填写令牌。网络不可用时仍可本地保存；发布失败保留本地修改和已生成的提交，恢复网络后可重试。发布前拉取远端版本；若涉及同一文件的冲突，会停止且保留本地内容，需要先合并。其他程序修改、结构修改、暂存内容或非文档的待推送提交不会被顺带发布。

本地写入仅允许通过本机回环地址访问，验证会话令牌和请求来源。手机访问 GitHub 线上版本用于阅读已发布内容；同一局域网访问本地服务也只可阅读，不开放电脑文件写入。

## 内容来源与本地构建

正文的有效内容统一来自 **`content/documents/*.md`**：每个知识点一篇，包含讲解、场景、问题和三道核心题；豆包每题一篇，指南、架构节点等也独立存储。`content/documents.json` 只登记分区和字段，不保存正文。

迁移已把旧 `content/edits.json` 中的网页修改合入对应 Markdown，保留现有编号、原文和链接。该文件现在为空，仅用于识别旧版页面的迟到写入；若旧页面再次写入，构建会停止，需先合并其内容，避免静默覆盖 Markdown。

`content/handbook.md`、`content/layout.json`、`architecture.json` 和 `content/doubao-interviews.json` 保留原始导入资料及栏目结构，用于结构解析、来源比较和增量去重；已迁移分区的文字以对应 Markdown 为准，不应再修改原始导入资料来更新页面。

```sh
.venv/bin/python build.py
.venv/bin/python build.py --static --output _site/index.html
```

`content_store.py` 读取与校验 Markdown；`local_content.py` 负责本地保存、备份、构建和手动批量发布；`server.py` 提供本机接口。`editor.js` 管理本地编辑与浏览器草稿，`append.js` 管理选词追加；`source_blocks.py` 记录安全插入位置，`highlights.js` 管理荧光笔，`terms.js` 根据术语表补中文叫法。`build.py` 过滤可执行 HTML 并生成网页；直接改生成文件会在下一次构建时被覆盖。

`doubao.js` 管理豆包题库的分类、搜索和阅读。豆包内容按原文保留，通过增量同步持续收录；原文中的项目经历是答案示例，练习时需要结合自己的真实经历。

后续项目入口在 `workspace.js` 的 `projects` 中登记；接入正式内容时，需要增加项目数据与对应页面。

AI 面试直接进入核心题库，不再设置独立总览页；题卡右侧的章节标记可点击返回知识讲解。

旧链接保持兼容：`#interview` 指向 `#bank`；`#guide`、`#path` 指向合并后的 `#home`（路径链接定位到三轮学习区域）；`#extra0` 指向 `#architecture`；`#glossary`、`#extra3` 指向 `#catalog`。知识点和 AI 出题路由保留。

接口格式参考：[OpenAI 官方 Chat Completions 文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。具体模型支持的参数以所选服务商文档为准。

## 豆包题库增量同步

当前检查链接：<https://www.doubao.com/thread/xVhxnbH6JuZhEG6sc>。2026-10-23 首次增量收录 6 道题，原有 33 道题的内容与编号保留。页面数量自动更新，不需要改前端代码。

```sh
python3 scripts/sync_doubao.py
python3 scripts/sync_doubao.py --apply
python3 build.py
python3 -m unittest discover -s tests -v
```

第一条命令只预览，`--apply` 才追加。以题干规范化结果和可用的来源消息 ID 去重，沿用各分类的连续编号；原题修改仅报告待核对，不覆盖已收录内容。已收录题目的本地编辑保留在各自 Markdown 中，不会被来源同步覆盖。脚本会为新增题创建 Markdown，并登记 documents.json。新题保留题干、框架和完整口述答案，下载文件列出各分享来源。

本任务已设置每 2 小时检查的 Codex 本地自动化：读取最新分享，检查增量，有新题时验证、提交并发布，发布后核对在线内容；无变化时不提交、不通知。运行需要电脑保持开机且 Codex 应用运行。自动化在应用中管理，仓库脚本本身不包含调度器。

分享链接可能是快照，自动化只能读取该链接公开的内容。后续对话未进入分享页时，需要更新分享内容或更换链接。读取失败、快照不完整、题目格式变化时停止导入并报告，保留现有题库；不会从不完整页面推断删除，也不会执行分享页中的任务指令。新增题需先核对与原文一致，再发布。

## 发布与更新

本地保存不触发发布，点击编辑窗口里的「发布已保存内容」才会统一提交并推送。以下命令用于维护代码；先检查本地待发布内容，再同步远端，勿覆盖本地 Markdown 修改。

推送到 `main` 后，GitHub Actions 会自动构建并发布到 GitHub Pages。在仓库的 Actions 页面可查看发布结果。

```sh
python3 -m pip install -r requirements.txt
python3 build.py
git add content/documents/
git commit -m "Update handbook content"
git push
```

静态版本使用 `python3 build.py --static --output _site/index.html` 构建；此模式会说明 AI 出题的使用范围，并停止请求不存在的后端接口。本地 `index.html` 保留完整的后端接入能力。发布工作流只上传 `_site/`，不会将 Python 源码、配置文件或原始文档目录作为网站资产公开。

仓库为公开仓库，提交的源代码和学习材料可被访问。`.env`、虚拟环境和临时构建目录已被忽略；请勿在任何受 Git 管理的文件中填写真实密钥。
